# Brain Cartridge

A personal knowledge base that runs inside Claude Desktop's Cowork mode. You feed it documents, it builds a searchable brain with a knowledge graph, and Claude uses your accumulated knowledge to sharpen every answer it gives you.

---

## Install

Open a new Cowork task in Claude Desktop, select an empty folder, and paste this:

```
Clone and set up a Brain Cartridge from https://github.com/cyclomaticsegal/brain-cartridge.git

1. git clone https://github.com/cyclomaticsegal/brain-cartridge.git .
2. bash bootstrap.sh
3. Read CLAUDE.md and follow its instructions.
```

That's it. Claude clones the repo into your folder, installs dependencies, and starts your brain. The whole thing takes about 30 seconds.

## What's in the box

| File | What it does |
|---|---|
| `brain.py` | The engine. Handles ingestion, hybrid search, knowledge graph, and export. |
| `brain.db` | SQLite database. All your data lives here: chunks, embeddings, graph nodes, edges. Starts empty. |
| `bootstrap.sh` | Installs Python dependencies at session start. The Cowork VM resets between sessions, so this runs every time. Takes about 30 seconds. |
| `graph-explorer.html` | Interactive D3.js visualisation of your knowledge graph. Open in any browser. |
| `GRAPH.json` | Graph data consumed by the explorer. Auto-regenerated by the engine, so never edit directly. |
| `CLAUDE.md` | Session startup instructions. Tells Claude to invoke the brain-bootstrap skill automatically on every session start. |
| `AXIOMS.md` | Your analytical frameworks. Claude reads this every session and uses it as the default lens for reasoning with you. Editable by both you and Claude. |
| `PROTOCOL.md` | Architecture reference. How the system is structured and why. |
| `INDEX.md` | Snapshot of what's in your brain. Updates as you ingest material. |
| `.claude/skills/brain-bootstrap/SKILL.md` | The behaviour layer. Tells Claude how to operate the brain, when to search, and how to manage your axioms. This is a hidden file (more on this below). |
| `DEMO-WALKTHROUGH.md` | Step-by-step guide to the demo experience. |
| `sources/` | Where ingested documents are archived after processing. |
| `inbox/` | Drop zone for new material. Put documents here, then ingest them. |
| `demo/` | Sample documents for the demo. Six files across three domains. Can be deleted after trying the demo. |

## First run

1. **Copy this folder** to wherever you like on your computer. Name it whatever you want: `my-brain`, `research-base`, anything.

2. **Open Claude Desktop** and create a new Cowork task.

3. **Select the folder** you just copied as the working folder when prompted.

4. **Say "start my brain"** (or "bootstrap", "set up my brain", etc.). Claude will run the bootstrap script to install Python packages (~30 seconds), initialise the database, welcome you, and ask you to name your brain.

That's it. The brain is live. It's empty, but it's ready.

## Adding material to your brain

The brain ingests `.md`, `.txt`, and `.pdf` files. The workflow is always the same: put files in the inbox, then tell Claude to process them.

### Step 1: Drop files in the inbox

Put your documents in the `inbox/` folder. You can use subfolders because the engine scans recursively. File names don't matter; the engine assigns standardised source IDs (S01, S02, etc.) during ingestion.

### Step 2: Ingest

In your Cowork session, say something like:

> "Process my inbox" or "Ingest the new files"

Claude runs the inbox command, which does the following in sequence:

1. Scans `inbox/` recursively for `.md`, `.txt`, and `.pdf` files.
2. Assigns each file the next available source ID (e.g. S01, S02).
3. Moves the file to `sources/` with a clean name (e.g. `S01-original-filename.md`).
4. Chunks the content into ~512-token segments with overlap.
5. Generates embeddings for each chunk (semantic vectors for search).
6. Auto-classifies the source into knowledge domains based on content.
7. Creates graph nodes and edges in the database.
8. Regenerates `GRAPH.json` and updates `graph-explorer.html`.
9. Cleans up empty folders left in the inbox.

After ingestion, your material is searchable immediately.

### What gets ingested and what doesn't

The engine skips certain directories: `_meta`, `.cache`, `__pycache__`, `predictions`, `node_modules`, `pre-built-thesis`, and `inbox` subfolders that are empty. It also skips system files like `brain.py`, `bootstrap.sh`, `PROTOCOL.md`, and `INDEX.md`.

Everything in `sources/` is fair game for re-ingestion if you ever need to rebuild the database from scratch.

## Searching your brain

Once you've ingested material, just ask Claude questions. The brain-bootstrap skill tells Claude when and how to search. You don't need to issue explicit commands. Claude decides whether to search based on your question.

Behind the scenes, the brain uses **hybrid search**: BM25 keyword matching (via SQLite FTS5) combined with semantic vector search (via sentence-transformers or TF-IDF fallback), fused using Reciprocal Rank Fusion. This catches both exact term matches and conceptual similarity across your ingested material.

If you want to run a search explicitly, you can ask Claude to do so, or use the command directly:

```
python3 brain.py search "your query here"
```

### Search options

| Option | What it does | Example |
|---|---|---|
| `--mode keyword` | Keyword-only search (BM25) | `search --mode keyword "tokenization"` |
| `--mode semantic` | Semantic-only search (vector similarity) | `search --mode semantic "what happens to human purpose"` |
| `--mode hybrid` | Both combined (default) | `search "energy constraints on AI"` |
| `--top N` | Return top N results (default: 10) | `search --top 5 "inflation"` |
| `--context` | Output formatted for Claude's context window | `search --context "innovation theory"` |
| `--verbose` | Show additional metadata per result | `search --verbose "blockchain"` |

## The knowledge graph

Every source you ingest becomes a node in a knowledge graph. The engine also creates concept nodes and domain nodes, with typed edges connecting them. This gives you a visual map of how your knowledge connects across domains.

### Viewing the graph

Open `graph-explorer.html` in any web browser. It renders an interactive D3.js force-directed graph. You can drag nodes, zoom, click for details, and filter by domain. The graph is empty until you ingest your first material.

### How the graph stays in sync

The engine keeps the graph up to date automatically. After every ingestion, tagging, or graph mutation, `brain.py` regenerates `GRAPH.json` (the data) and updates the legend in `graph-explorer.html`. You never need to edit either file by hand. If they ever get out of sync, run:

```
python3 brain.py export-graph
```

This regenerates both files from the database, which is always the source of truth.

### Querying the graph programmatically

To explore what's connected to a specific node:

```
python3 brain.py graph C11              # show direct connections
python3 brain.py graph C11 --hops 2     # show connections within 2 hops
```

## Knowledge domains

The engine auto-classifies each source into knowledge domains using TF-IDF similarity against domain keyword descriptions. The brain cartridge ships with 12 general-purpose domains:

1. Macroeconomics & Monetary Systems
2. AI & Machine Intelligence
3. Blockchain, Tokenization & Ownership
4. Innovation & Disruption Theory
5. Energy & Physical Infrastructure
6. Political Economy & Governance
7. Human Purpose & Meaning
8. Geopolitics
9. Meta / Personal
10. Applied Practice & Consulting
11. Predictions & Forecasting
12. Methodology & Meta-Cognition

These are defined as keyword bags in `brain.py` (the `DOMAIN_DESCRIPTIONS` dictionary in the `classify_source` function). You can edit them to match your own intellectual territory. If you work in medicine and law rather than macroeconomics and blockchain, change the domain names and keywords to fit.

### Manual tagging

If auto-classification gets a source wrong, you can override it:

```
python3 brain.py tag S05 3,4 "digital ownership, network effects"
```

This assigns source S05 to domains 3 and 4 with the given theme description.

## Building your axioms

This is the most important part of the system and the one that takes the most time. Your axioms are the analytical frameworks that Claude loads into context on every interaction. They tell Claude how you think: which lenses you apply, which cross-domain connections you care about, which questions you always ask.

Axioms are not predictions, conclusions, or positions. Those are content, and they belong in brain.db as ingested material. Axioms are *instructions*. They tell Claude what to look for and how to reason.

### Where axioms live

In `AXIOMS.md` in the root of your working folder. This is a regular markdown file you can open and edit directly. Claude also writes to it (with your approval) when proposing new frameworks or refining existing ones.

The hidden file `.claude/skills/brain-bootstrap/SKILL.md` tells Claude *how to use* your axioms: when to read them, when to propose changes, how to apply them. You generally don't need to edit SKILL.md unless you're changing the brain's operational behaviour.

### How axioms get built

There are two paths, and most people use both.

**Top-down: You declare your frameworks.** On first run, Claude asks what intellectual interests or analytical lenses you already have. You name them: "network effects", "innovation theory", "energy constraints", whatever you think through regularly. Claude writes initial entries in AXIOMS.md based on your description and general knowledge.

**Bottom-up: Patterns emerge from your material.** As you ingest sources, Claude watches for recurring themes across domains. When a pattern appears in multiple sources, Claude proposes a new axiom: "Your material keeps returning to [theme]. Want me to add this as a framework?" You approve, refine, or reject. Claude never adds axioms without your agreement.

### What makes a good axiom

A good axiom is recurring (you keep coming back to it across topics), connective (it bridges domains that don't usually talk to each other), and actionable (it changes what Claude looks for). "Innovation matters" is not an axiom. "Innovation is cumulative recombination; look for combinatorial potential and network effects before evaluating any new technology" is.

### How axioms relate to the brain

Your axioms are signposts. Your brain (brain.db) holds the depth. When Claude encounters a question where one of your axioms applies, it uses the axiom to know *which lens to apply*, then searches your brain for the detailed material on that framework. The axiom says "consider network effects here." The brain contains your ingested material on how network effects work.

### Axiom refinement

After every ingestion, Claude reviews your axioms against the new material. It may propose sharpening an existing axiom, adding a new one, or noting which sources are relevant to which frameworks. You always approve changes before they're written.

Over time, your axioms become a precise map of how you think. A personalised analytical operating system that Claude applies automatically.

## All brain.py commands

Here's the complete command reference.

| Command | What it does |
|---|---|
| `brain.py inbox` | Process all files in `inbox/`: assign IDs, move to `sources/`, ingest, update graph. This is the primary way to add material. |
| `brain.py ingest` | Re-ingest all sources from scratch. Rebuilds the entire database. Use if you need a clean slate or changed the chunking parameters. |
| `brain.py search "query"` | Hybrid search across all ingested material. See search options above. |
| `brain.py graph <node_id>` | Show all nodes connected to the given node. Add `--hops N` for multi-hop traversal. |
| `brain.py export-graph` | Regenerate `GRAPH.json` and update `graph-explorer.html` from the database. |
| `brain.py update-html` | Update `graph-explorer.html` only (without rewriting `GRAPH.json`). |
| `brain.py tag <source_id> <domains> ["themes"]` | Manually assign a source to domains. Example: `tag S05 3,4 "digital ownership"` |
| `brain.py sync` | Run post-ingest sync: update INDEX.md stats and reconcile derived files. |
| `brain.py stats` | Print brain statistics: source count, chunk count, node/edge counts, domain breakdown. |
| `brain.py ingest-prediction <model_id> [path]` | Ingest a prediction narrative into the brain. Used with external prediction systems. |

In practice, you rarely type these commands yourself. You talk to Claude, and the brain-bootstrap skill tells Claude which command to run. But they're here if you want to run them manually or understand what's happening under the hood.

## How sessions work

Each time you open a Cowork task, Claude Desktop spins up a fresh Linux VM with a new random name (like `charming-purple-fox`). Your working folder is mounted into this VM via FUSE.

There's a subtlety: SQLite doesn't work reliably over FUSE mounts (it uses WAL mode, which requires a real filesystem). So `brain.py` automatically copies `brain.db` from your working folder into the VM's local session directory at startup. After every write operation (ingestion, tagging, graph mutation), it copies the database back to your working folder for persistence.

This means:

- Your data always survives between sessions. It's on your actual computer.
- Each session starts by restoring from the last write. No data loss.
- You never need to think about this. It's automatic.

The session detection is dynamic. `brain.py` scans `/sessions/` to find whatever session directory exists, so it works regardless of what name the VM gets.

## Troubleshooting

**"bootstrap.sh failed"** This usually means a pip install timed out. Run it again. If sentence-transformers fails to install, that's fine. The engine falls back to TF-IDF automatically. Search quality is slightly lower but still functional.

**"No results found" when searching** Check that you've actually ingested material: run `brain.py stats`. If sources are 0, nothing has been ingested yet. Drop files in `inbox/` and run `brain.py inbox`.

**Graph explorer is blank** Run `brain.py export-graph` to regenerate `GRAPH.json` and update the HTML. Then refresh the browser.

**"brain.db is locked"** This can happen if two operations try to write simultaneously. Wait a moment and try again. In a Cowork session, Claude handles serialisation automatically.

**Want to start over?** Delete `brain.db` and the contents of `sources/`. Run `brain.py ingest` (which will find nothing) or just start dropping new files in `inbox/`. The engine creates a fresh database automatically.
